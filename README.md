# Генерация карточек товаров с помощью LLM

Рабочий репозиторий проекта генерации карточек товаров.

# Отчёт по проекту

## Финальный конфиг
- модель: `Qwen/Qwen2.5-1.5B-Instruct`
- dtype:
- параметры запуска vLLM: `nohup vllm serve Qwen/Qwen2.5-1.5B-Instruct --dtype half --max-model-len 4096 \
  --gpu-memory-utilization 0.9 --enforce-eager --port 8000 > vllm.log 2>&1 &`
- стратегия длинного входа:
- при браке формата выполняется повторная генерация с указанием модели причины ошибок;
- максимальное число попыток генерации: 2.

Анализ кэшированных результатов показал, что ошибки, устраняемые повторным запросом, устраняются со второй попытки; если вторая попытка не помогает, то и третья не дает ощутимого выигрыша.

## Параметры генерации
На этапе настройки промпта и базовых параметров эксперименты проводились на `dev.jsonl` из 40 товаров.

Валидация проверяла:
- корректность JSON;
- наличие обязательных полей;
- совпадение `product_id` с исходным товаром;
- количество предложений в `description` и их общую длину;
- количество элементов и отсутствие пустых строк в списках `pros`, 'cons`, 'tags`.

В таблице показаны результаты без ограничения `top_k`. Варианты `top_k=20` и `top_k=50` также проверялись, но устойчивого улучшения не дали.

Выбранные параметры не гарантируют фактическую точность: в тексте встречаются галлюцинации и смысловые ошибки, часть которых связана с противоречивыми исходными данными - атрибуты товара и отзывы иногда не согласуются между собой.

| max_tokens | valid_rate | avg. attempts | avg. output tokens | обрезано |
|---:|---:|---:|---:|---:|
| **250** | **95%** | **1.15** | **209.4** | 2 |
| 350 | 90% | 1.15 | 219.8 | 1 |
| 500 | 90% | 1.15 | 227.3 | 1 |

Увеличение `max_tokens` не улучшило результат, поэтому выбрано минимальное из проверенных значений - `250`.

Итог: `temperature=0.5`, `top_p=0.9`, `top_k` без ограничения, `repetition_penalty=1.1`, `max_tokens=250`, `max_attempts=2`.
