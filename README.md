# Генерация карточек товаров с помощью LLM

Рабочий репозиторий проекта генерации карточек товаров.

# Отчёт по проекту

## Финальный конфиг
- модель: `Qwen/Qwen2.5-1.5B-Instruct`
- dtype:
- параметры запуска vLLM: `nohup vllm serve Qwen/Qwen2.5-1.5B-Instruct --dtype half --max-model-len 4096 \
  --gpu-memory-utilization 0.9 --enforce-eager --port 8000 > vllm.log 2>&1 &`
- стратегия длинного входа:
- при браке формата выполняется повторная генерация с указанием модели причины ошибок;
- максимальное число попыток генерации: 2 (**почему?**)

## Параметры генерации
На этапе 2 подбирались системный промпт, значения `temperature` и `top_p` и максимальное число попыток генерации.
Эксперименты проводились на `dev.jsonl` из 40 товаров.

Валидация проверяет:
- корректность JSON;
- наличие обязательных полей;
- совпадение `product_id` с исходным товаром;
- количество предложений в `description` и их общую длину;
- количество элементов и отсутствие пустых строк в списках `pros`, 'cons`, 'tags`.

Если карточка не проходит валидацию, выполняется повторный запрос с указанием модели причины ошибки и инструкцией по исправлению.

В последнем прогоне валидны 33 из 40 карточек (82.5%). Причины оставшихся ошибок: `long_input` - 5 карточек, `wrong_list_length` - 1 карточка, `description_length` - 1 карточка.

Ошибки `long_input` на этом этапе не устранялись, так как стратегия обработки входов длиннее 1500 токенов предусмотрена на этапе 4.

Также анализ кэшированных результатов показал, что ошибки, устраняемые повторным запросом, устраняются со второй попытки; если вторая попытка не помогает, то и третья не дает выигрыша. Поэтому число попыток ограничено двумя для снижения расхода токенов.
